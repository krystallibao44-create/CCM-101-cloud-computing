# Mission Reflection

**1. Which cloud infrastructure component do you think is the most important? Why?**

If I had to pick one, I'd say compute is the most critical piece of cloud infrastructure. Everything else — storage, networking, identity management — only matters if there's something actually processing and acting on it. Compute is the part that takes raw data and network traffic and turns it into something the end user can actually see or use. Without it, the rest of the stack is just sitting there doing nothing.

**2. How does Linux support cloud computing?**

Linux is basically the backbone of most cloud infrastructure today. The majority of servers, containers, and virtual machines in the cloud are built on Linux because it's stable, free to modify, and lightweight enough to run efficiently at scale. What really makes it useful for engineers is the direct terminal access it gives — you can check resource usage, manage running processes, and set up networking all through simple commands, which is exactly what we practiced in this activity.

**3. Why is technical documentation important before deploying infrastructure?**

Before anything gets deployed, documentation is what makes sure the reasoning behind every decision isn't lost. It gives the team something to refer back to if something breaks, it keeps everyone on the same page during collaboration, and it reduces the chance of expensive mistakes that come from guessing instead of knowing. Basically, it's the difference between building something intentionally versus building it blindly.

**4. What new skills did you learn during this laboratory activity?**

This activity taught me how to actually dig into a live Linux environment through the terminal — pulling out details like the OS version, CPU specs, memory, and disk usage instead of just reading about them. On top of that, I got more comfortable comparing how different cloud providers offer the same kind of service under different names, and I practiced writing clean, professional documentation in Markdown.

**5. How has your GitHub portfolio improved after completing this mission?**

My repository looks a lot more like an actual professional portfolio now instead of just a random collection of files. Everything is organized into a clear folder structure with proper reports, comparisons, and diagrams, and I got practice committing changes in a structured, meaningful way — which is closer to how documentation actually works in a real cloud engineering job.
